# 04 · 播报链路（main.rs 状态机 + announcer.rs + logger.rs）

## 职责

从 OCR 候选到"出声+留痕"：确认候选真实性 → 去重 → 文案生成 → 队列播报 → CSV 日志。

## 确认状态机（main.rs run()）

OCR 单轮 1.6~4.8s，不能每帧都跑；识别结果也不能跑一次就播（误读播出去就是事故）。
非阻塞状态机在主循环里流转，全程无 sleep：

```
 Idle ──变化触发──▶ OCR轮 ──有候选──▶ Confirm(等 stable_frames 轮复现)
   ▲                 │                    │
   │            无候选(退避)              ├─复现一致─▶ 播报 ──▶ Idle
   └──────────────────┘                    │
                                    静帧快速确认(连续 static_confirm_ticks
                                    轮画面无变化) ──▶ 播报 ──▶ Idle
```

| 机制 | 解决的问题 |
|---|---|
| 多轮投票确认 | 单次误读不播报（候选须跨轮复现一致） |
| 静帧快速确认 | 屏面已静止、候选出现过一次即可确认，**省掉第二轮 OCR**——它是 5~10s 端到端延迟的最大单项（2026-09-28 延迟专项结论） |
| 确认 TTL `max(cfg, 3×OCR耗时)` | OCR 慢时自动放宽窗口，避免永远确认不上 |
| 空转退避 | 变化触发但读不出号码时，兜底 OCR 间隔 2ⁿ 递增至 30s，不烧 CPU |

兜底 OCR 间隔另有两档：常规 `fallback_ocr_sec`(3s)、静帧时放宽 `static_fb_sec`(10s)
——屏面静止且上轮已读出内容时反复重读同一批像素纯烧 CPU（实测占满一核）。

## 播报器（announcer.rs）

- **去重 TTL**：`(号码, 窗口)` 在 TTL 内不重播；TTL 取 `max(ttl_sec, 3×OCR耗时)`，
  兼顾"翻页回来还在屏上"与"同一号两次叫号"
- **独立播报线程 + 队列**：识别主循环永不阻塞在音频上；队列有深度上限（丢最旧），
  防止密集换屏时播报积压到毫无意义

## 语音文案模板

```
template: "请{number}到{window}号窗口办理"
spell_number: true  →  GA200 → "G A 二 零 零"（逐字中文读，详见 05-tts.md）
```

## CSV 日志（logger.rs）

每次播报写一行：`时间戳,号码,窗口,原始OCR文本,状态`。

可靠性约定（与 Python 版一致）：

- **日志写失败绝不带崩播报主程序**：文件被预览器/杀毒短暂占用时重试
  3 次（0.3s/0.6s 间隔），仍失败则打印告警并丢弃该条
- `utf-8-sig` BOM：仅新建空文件时写，Excel 直开不乱码
- `csv_escape` 与 Python csv.writer 对齐：含逗号/引号/换行才加引号，引号翻倍
  ——原始 OCR 文本可能包含任何字符，必须转义

`save_trigger_frames=true` 时每次 OCR 触发把所见画面存到 `_live/`，
与日志 CSV 配合可完整回放"当时看到了什么"。

## 相关配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `detect.stable_frames` | 2 | 复现确认轮数 |
| `detect.confirm_ttl_sec` | 4.0 | 确认窗口（下限 3×OCR 耗时） |
| `detect.static_confirm_ticks` | 2 | 静帧快速确认轮数，0=关闭退回两轮投票 |
| `detect.ttl_sec` | — | 播报去重窗口 |
| `log_file` | `announce_log.csv` | 日志路径 |
