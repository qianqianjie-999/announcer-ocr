# 03 · 识别解析（ocr.rs）

## 职责

把增强图变成结构化的 `(号码, 窗口)` 候选集合：tesseract 子进程调用 →
文本噪声清洗 → 双正则提取 → 形近字归一化。

## tesseract 子进程调用

[recognize()](../src/ocr.rs#L13)：

- `OMP_THREAD_LIMIT=1`：tesseract 默认开满核并行，会**拖慢主循环里并发的
  帧差检测**，实测单线程反而整体更快
- **超时 10s + 管道排空**：psm11 偶发"病态帧"要 15~20s 才出结果，不设超时会
  拖死主循环；杀进程前必须排空 stdout 管道，否则子进程写管道阻塞、杀不掉变僵尸
- stdin 喂 JPEG，stdout 收 UTF-8 文本，无临时文件

默认参数：`chi_sim` 单语言 + psm 11（稀疏文本）+ dpi 150。
chi_sim+eng 慢 33% 且无精度增益（J1850 靶机实测），故不加英文包。

> **psm 11 只对"单行窄条"成立**。ROI 扩成覆盖三行的大区块（主码流多行列表）后
> 必须改 **psm 6**，否则读出 `Al4smpx和D` 这类垃圾（2026-10-22 现场：
> 同图 psm 6 完美读出"请GA166到C04号窗口办理"，psm 11 全废）。
> 详见 [07 · 实战排障手册](07-troubleshooting.md)「切到主码流后一个号都读不出」。

## 噪声清洗（clean_ocr_noise）

白字深底 + 中文语境下的稳定误读模式，三条规则全部来自靶机实测样本：

| 规则 | 误读样本 | 清洗后 |
|---|---|---|
| ① 去 `?` 与全部空白 | `GA9?99` | `GA999` |
| ② 号码前缀数字冒充字母（仅当后跟 3~4 位数字再接"到/至"） | `6A777到` / `64999到` | `GA777到` / `GA999到` |
| ③ "到"后误插 0 | `到0C01` / `到003号` | `到C01` / `到03号` |

规则②的还原表：`6→G / 4→A / 8→B / 5→S / 2→Z`。
**O/0、I/1 不还原**——与号码内部的 O→0 归一化方向冲突，且误还原因果严重。
"后跟 到/至"是硬条件，时间戳等普通数字天然免疫。

## 正则解析与归一化

[parse()](../src/ocr.rs#L177) 对清洗后文本跑配置的正则集合（默认双正则）：

```regex
([A-Z]{1,2}\d{3,6})                                # 仅号码 → (号码, "")
([A-Z]{1,2}\d{3,6})[到至]([A-Z]{0,2}\d{1,3})[号窗]  # 号码+窗口
```

- `split_prefix`：前缀至多 2 个大写字母，`"GA999" → ("GA","999")`
- `norm_digits`：形近归一化 `O→0 / I→1 / l→1`，只作用于字母后的数字段
- `fold_window_zeros`：窗口号前导零折叠 `C001 → C01`——"C01" 被读成
  "CO01" 再经 O→0 归一化会变成 "C001"，与真窗口是不同去重键，导致同号
  重复播报（2026-10-07 实测踩坑后新增）。尾零 `C10`、纯数字窗口 `03` 不受影响

输出 `HashSet<(号码, 窗口)>`——同一屏多张卡天然支持，迭代前排序保证确定性。
