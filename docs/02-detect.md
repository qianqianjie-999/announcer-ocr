# 02 · 变化检测（detect.rs）

## 职责

判断"画面有没有变"，只在变化时触发 OCR。目标：屏面静止时零 OCR 消耗，
换屏后 1~2 帧内必触发（阈值 0.0015 下不漏检）。

## 检测前处理流水线

[prepare()](../src/detect.rs#L14)：

```
整帧 RGB → 裁 ROI(越界自动收敛) → 灰度 → 缩到宽≤480 → 高斯模糊 blur5
```

缩到 480 宽是为了帧差计算量恒定（与摄像头分辨率无关）；blur5 抹平传感器噪声。

## 亮度对齐帧差（算法核心）

[change_ratio()](../src/detect.rs#L79)：

```rust
shift = mean(cur) - mean(prev);          // 全帧均值漂移
p2 = (shift.abs() >= 1.0) ? (p + shift) : p;
ratio = |cur - p2| > diff_threshold 的像素占比;
```

**为什么必须先对齐再比**：摄像头自动曝光会持续微调整帧亮度，原始 absdiff
会把漂移当成"画面变化"，导致空场景反复触发 OCR。对齐后阈值才能压到
`changed_ratio = 0.0015`（0.15% 像素超阈值即判定变化）而不漏检。

方向性说明：对齐会把"局部变化 + 均值偏移"放大为全帧命中——**过触发是安全的**
（多跑一次 OCR），漏触发才致命，所以不做反向补偿。

## OCR 图像增强（enhance_for_ocr）

触发后给 tesseract 的图不是原帧，而是 [enhance_for_ocr()](../src/detect.rs#L105) 的输出：

```
2x 放大 → 取红通道 → Otsu 大津法自动阈值二值化 → 反相(白底黑字)
```

每一步都有实测依据：

| 步骤 | 原因 |
|---|---|
| 2x 放大 | ROI 缩到 480 宽后文字太小，tesseract 识别率骤降 |
| **红通道** | 叫号屏/测试卡都是"白字深底"：白字三通道都高、深蓝底只有红通道最低——取红通道等价于把字/底对比拉到最大。灰度版会被蓝底抬高，实测输出明显更差 |
| Otsu 二值化 | 不加阈值时"号窗口"糊成"写窗"，正则套不上（两种都试过，差别就在这一步） |
| 反相 | tesseract 偏好白底黑字 |

靶机实测（401×180 ROI 拍打印测试卡）：原图 psm11 → 全乱码；
本增强 + psm11 → 两张卡 4 个号全部可解析。

## 相关配置（detect 节）

| 字段 | 默认 | 说明 |
|---|---|---|
| `diff_threshold` | 25.0 | 单像素灰度差阈值（0-255 尺度） |
| `changed_ratio` | 0.0015 | 超阈像素占比 → 判定画面变化 |
| `save_trigger_frames` | true | 触发帧存证到 `_live/`（排障必备） |
